3 · State names (exact, per epic §10)

Authoring: draft → validating → invalid | ready → diff → applying → persisted | runtime-only | conflict. Runs: idle → running → complete | partial | failed | unknown-outcome | blocked-missing-dependency (cancelled/timed-out are UX-11, Release B). Connection: process-up, ready, not-ready, unreachable, stale. Logs: live, disconnected, gap-unresolved, empty-window, truncated-capture. No "saved" indication before server confirmation.

4 · Proposed token additions (need sign-off)

  • Dark-mode semantic foregrounds: --sr-success-fg/warning-fg/danger-fg/info-fg brightened under [data-theme="dark"] (values in workbench.css §1) — light-canonical values fail 4.5:1 on dark surfaces. Same hues, luminance only.
  • Dark-mode semantic backgrounds: opacity bumped .12→.16–.18 for visibility on dark.

5 · Responsive behavior

  • ≥960px: sidebar + two-column worksheet grids.
  • <960px: sidebar becomes a horizontal scrollable tab row; all grids stack to one column; instrument strip horizontally scrolls, no cells dropped; receipt grid 2-up.
  • Authoring stays enabled at narrow widths and browser zoom — stacked forms replace side-by-side, never a read-only fallback. Mobile priority is triage (Overview, Investigate) per brief.

6 · Accessibility requirements (WCAG 2.2 AA)

  • Contrast: annotations in Components doc; verify dark semantic tokens after any change.
  • Status = dot + text everywhere; unknown is textual ("not executed · unknown").
  • :focus-visible 2px ring on all interactive elements; dialogs trap focus, Esc cancels; conflict card role="alertdialog"; banners role="alert"/status so async errors are announced.
  • Keyboard-complete: every drag (React Flow) keeps the node list/table alternative; ⌘K is an accelerator, never the only path.
  • prefers-reduced-motion collapses the only animation (pulse dots).
  • Destructive dialogs: exact-name entry gates the action; destructive button never auto-focused.

7 · Acceptance walkthrough (prototype test)

  1. First-time developer: identify connected server (instrument strip) → open starter agent → edit → validate → diff → apply → read persisted receipt → run pipeline → find failed node (rag-lookup, null response) → export evidence. No facilitator needed.
  2. Switch role to viewer: editor shows explained lock, not breakage; Test Lab still runs; audit/tenants state their floors.
  3. Set connection to unreachable: frozen snapshot labels, disabled writes, preserved draft, no auto-retry.
  4. Set install to empty: onboarding explains pipeline creation is out of scope; no dead Run button.
  5. Trigger conflict (checkbox in diff card): both drafts preserved; reload vs reviewed overwrite.
  6. Admin: tenant deletion states impact and requires exact name; minted key shown exactly once.

8 · Unresolved decisions (do not implement by inference)

  • Agent conditional-write route: additive If-Match route vs versioned transition; legacy unconditional writers disclosed in conflict copy either way. Blocks UX-03 backend work.
  • Durable drafts: Release A designs assume browser-memory drafts + explicit export; a durable draft store needs retention/encryption policy sign-off.
  • Log recovery cursor: gap-unresolved state ships either way; a stable cursor (NEW) upgrades gaps to backfillable.
  • Cost on Overview: omitted by design; product may re-add with full estimate labelling.
  • Dark semantic tokens: §4 above needs design-system owner sign-off.
