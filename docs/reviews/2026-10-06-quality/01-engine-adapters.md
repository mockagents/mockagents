## 4. Design observations

**D-1 · The handler skeleton is copied seven times and the copies have already diverged.** OpenAI, Anthropic, Gemini, Responses, Ollama and Bedrock each repeat the same sequence:

- decode, with a 413/400 split;
- convert the request;
- call the engine;
- map errors: chaos (connection vs Retry-After), strict, then engine error;
- stamp RequestMeta and set headers;
- stream or write JSON.

Observed drift: error `type` for 500s (E-14), 413 handling (E-21), Bedrock stream connection faults (E-12), Ollama/Bedrock strict errors rendered as a generic 400, and the refusal+content rendering split three ways (L-14). The proposal is the audit's R3:

```go
type provider interface {
    Decode(r) (*engine.InboundRequest, wireCtx, error)
    RenderError(w, status int, kind, msg string)
    RenderChaos(w, *engine.ChaosError)
    RenderStrict(w, *engine.StrictToolError)
    Render(w, *engine.Response, wireCtx)
    Stream(ctx, w, *engine.Response, streaming.Plan, wireCtx) error
}
```

`dispatch(p)` would own the skeleton once. A table test then iterates `DefaultRegistry` LLM routes × {chaos 429, connection, strict, ErrAgentNotFound, template-500} and asserts every provider's mapping.

**D-2 · The streaming plan is private, so new emitters cannot use it.** Four hand-rolled `chunkSize`/`delayMs` resolvers exist (`streaming/openai.go:85-94`, `anthropic.go:115-124`, `gemini.go:65-74`, `adapter/responses_stream.go:42-52`). There are two identical byte splitters (`chunkString`, `chunkArguments`; the root of E-02) and two identical ctx sleeps (`sleepCtx`, `sleepResponses`). The pacer is unexported, which is why Responses, Ollama and Bedrock silently ignore stream physics (E-08). Proposal: export `streaming.Plan` built from `*types.StreamingConfig`, with `FirstByte(ctx)`, `BeforeChunk(ctx,i,n)`, `BeforeArgDelta(ctx,i)`, `TextChunks(s)` and a rune-safe `ArgChunks(s)`. Every emitter, including Bedrock EventStream and Ollama NDJSON, consumes it, and the duplicates are deleted.

**D-3 · The engine result lacks the context adapters need.** Adapters re-resolve the agent to find its streaming config (L-20), and the engine cannot know which wire it is answering (E-07). Proposal: add `InboundRequest.WireProtocol` and `Response.Streaming *types.StreamingConfig` (or `Response.Agent`). This removes the four re-resolution blocks and the reload race.

**D-4 · Session-identity policy is scattered.** It lives in `extractSessionID` (`adapter/openai.go:513`), `responsesSessionID` (`responses.go:651`), the Realtime connection id (`realtime.go:408`), pipeline node scoping (`engine/pipeline.go:342`) and the batch dispatcher (none). E-01 and E-23 are both policy bugs. Proposal: one `engine.SessionKey` helper or policy. Rules: explicit header wins; a Responses chain carries the session id stored with the response; a conversation uses its id; everything else is `""` (throwaway).

**D-5 · Bounded-store boilerplate.** `responseStore`, `conversationStore`, the minted-key map, `anthropicCacheTracker`, the files/batches stores and the vector store each hand-roll FIFO-by-count. None budgets bytes, and tenant scoping is inconsistent (Responses global, Conversations per tenant). Proposal: a generic `bounded.Store[K,V]{MaxEntries, MaxBytes, PerTenant bool, SizeOf func(V) int}` with one eviction test suite (E-15).

**D-6 · Billing policy is a path list, not route metadata.** E-04 and E-06 are two more instances of the audit's F2/R1 (hand-maintained `isLLMProviderPath`). Proposal: `adapter.Route{Billable bool}`, with the quota middleware deriving from it. Internal dispatchers (batches) must call the same quota and spend hooks Realtime already receives (`CheckQuota` / `OnResponse`).

**D-7 · Tool-call arguments are never templated.** `Generate` renders only `content` (`engine/response_generator.go:107-123`). A regex capture such as `weather in (?P<city>\w+)` cannot flow into `get_weather(city=…)`, which is the most common reason to capture at all. Proposal: render string leaves of `Arguments` with the same `TemplateContext`, cached per string, and clone the map rather than aliasing the registry's (today `resp.ToolCalls` aliases `scenario.Response.ToolCalls`; this is safe only because nothing writes it in place).

**D-8 · Token accounting is spread across many formulas.** `EstimateTokens` (adapter), Realtime word counts (`realtime.go:529-533`), streaming defaults (`25`, `len/4+1`) and per-adapter subtractions (cache, thinking). Proposal: one `usage` helper, `Prompt(msgs, tools, images)` and `Completion(resp)`, returning a struct every renderer and streamer consumes. This closes L-18, E-09 and the remaining M-18 drift together.

**Still present from audit §3.3:** `ProcessRequestContext` remains a ~300-line function with a ~145-line closure (`engine/engine.go:176-479`). It also performs synchronous log I/O (`e.Logger.Info/Warn` at `:338,351,386,394,432,439,446`) while holding the per-session lock, so slow stderr back-pressure serialises a session's turns.
