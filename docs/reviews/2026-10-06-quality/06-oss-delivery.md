# Review 06: open-source standards, supply chain, CI/CD, packaging and docs accuracy

**Target:** `github.com/mockagents/mockagents` @ `origin/main` `9fa4db7` (worktree `mock-agents-qloop`). Reviewed 2026-10-06, read-only.
**Method:** I read every workflow, the release scripts, packaging manifests, community files and the Helm chart. I queried the live repository with read-only `gh api` calls (rulesets, community profile, Pages, Dependabot, code- and secret-scanning, runs, PRs and issues), and the public registries with anonymous GETs. Anything I reproduced was run in a scratch copy outside the repo: `npm ci` for `sdk/npx`, the Python job from `verify.yml` in a clean venv, `gofmt -l`, `mkdocs build --strict`, `go mod tidy -diff`, and the four docs-check tools.
**Severity:** S1 = security or legal exposure. S2 = a standard artifact is missing, or a broken process that a contributor or user will run into. S3 = polish.

**Headline:** the CI design is unusually careful (actions pinned by SHA, `contents: read` everywhere, CodeQL, govulncheck, Dependabot). Around it, though:
- The live repo state shows real problems: unclaimed package namespaces, no review gate on `main`, a release gate that has never run and fails, a docs site serving the wrong content, an install-path monitor that has been red for 26 days, and unanswered contributors.
- Licensing for redistributed artifacts is incomplete: no third-party notices, no LICENSE file in the SDK packages, and unattributed Lucide-derived icons.
