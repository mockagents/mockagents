# Design decisions and trade-offs

This is an analysis of the implemented design. The rationale column explains why the choice fits this product; it is not a claim that every choice had a historical ADR. Suggested alternatives are future options, not shipped capabilities. Costs below are qualitative; performance conclusions require measurement.

| Implemented decision | Alternatives | Benefits and justification | Costs / complexity / maintainability | Scale, performance and reliability consequences |
| --- | --- | --- | --- | --- |
| Neutral engine behind wire adapters | One implementation per provider; generated gateway only | Shared scenario/tool/session behavior with independently accurate serialization | Normalization can lose provider detail; adapters still need rich conformance tests | Fast in-process calls, but shared engine bugs affect several providers |
| Go modular monolith | Separate microservices; script-only mock library | Single binary, simple local/CI lifecycle and no network hop between components | Broad repository requires clear package ownership | One-process blast radius; horizontal scaling needs explicit state strategy |
| YAML/JSON declarative fixtures | Arbitrary scripts/plugins; recorded responses only | Reviewable data, validation and reproducible edge cases | Expressiveness bounded by matcher/template/schema; broad schemas must stay aligned | Low execution overhead; no sandbox for arbitrary user code is needed because none is loaded |
| Ordered rules with explicit defaults | Semantic/LLM matching; priority scoring | Predictable rule selection and cheap tests | Order is behavior; broad rule can shadow narrower cases | Linear scenario sweep with regex/lowercase caches; no semantic understanding |
| Cached Go templates | Pre-render every fixture; custom language; strict missing-key errors | Existing language/functions and good author iteration | Missing fields can silently produce placeholder text; cache lifetime follows process | Low warm-path allocation; high fixture churn can retain cache entries |
| Locked in-memory sessions | Database transactions for every turn; append-only event log | Simple fast isolated turns and rollback on generation errors | Shared pointer contract requires disciplined locking; not durable | Per-session serialization; bounded memory; restart/replica routing loses continuity |
| Definition-order parallel result collection | Completion-order results; worker queue | Stable output ordering despite concurrent execution | Goroutine count follows pipeline/tool fan-out; no built-in backpressure scheduler | Good independent-node latency; not suitable as a durable workload queue |
| Depth-first graph traversal, execute-once nodes | Topological fan-in scheduler; actor system | Small implementation for conditional fixture paths | Diamond behavior must be explicit; no join/reducer/retry semantics | Predictable traversal, limited workflow expressiveness |
| Pure-Go SQLite for local stores | External DB mandatory; cgo SQLite; all memory | Zero-service setup and portable build | SQL migrations/retention still need maintenance; local files need backups | One host/pod owns logs; race detector separately needs a C compiler |
| Optional Postgres tenancy | Redis/shared all-state service; SQLite-only | Shared credentials/settings/spend without changing engine ownership | Two stores require conformance and mutation tests | Improves control-plane sharing, does not distribute sessions/catalog/logs/rate buckets |
| Role-floor chokepoint plus handler ownership | Per-route ad hoc checks; central role check only | Missing policy fails at mount; tenant ownership stays resource-specific | Two layers must stay aligned; identity capability mapping must follow mounted routes | Consistent protection on managed APIs; open provider routes remain a deliberate separate policy |
| Auth-exempt provider paths with optional principal | Require MockAgents key for every route | Existing SDK keys work in local/shared test environments | Wrong key can silently become anonymous; global fixtures still reachable | Network isolation remains important; quotas only cover applicable scoped traffic |
| Optimistic agent/pipeline editing | Last-write-wins everywhere; pessimistic editor lock | Prevents cooperating editors from overwriting changed definitions | Legacy unconditional agent writes can still clobber; ETag differs from effective revision | Atomic file replacement avoids torn definitions, but no distributed registry invalidation |
| Bounded asynchronous interaction logging | Synchronous durable log transaction before response | Keeps diagnostic persistence off the request hot path | Backpressure/drop accounting and shutdown flushing required | Eventual/best-effort evidence rather than complete transactional capture |
| Separate MCP/A2A serving modes | Fold all protocols into one router/engine | Protocol lifecycle stays explicit and usable over stdio/standalone HTTP | Separate auth, port, shutdown and fault wiring | Main-server middleware guarantees cannot be assumed on these listeners |
| Hash-indexed JSONL record/replay | SQL cassette store; provider-specific fixture conversion only | Portable reviewable captures and fast lookup; per-key response sequences | Body canonicalization/encoding/redaction and torn-write handling are nontrivial | Entire cassette indexed in memory; append efficient; query not in default match key |
| SDK-managed binary vs reimplement mock in each language | Native Python/JS engines | One behavior implementation across language users | Download/version/checksum/subprocess lifecycle is a maintained security boundary | Cold install cost; tests require binary availability unless using limited Go in-process mode |
| Server-rendered GUI with small client islands | Full SPA/global client store; static generated console | Fresh server data and server-side credential forwarding | Server actions/proxy/cookies and timeouts must agree | Backend availability affects renders; explicit unknown/error UI preserves trust |

## Design patterns and avoided failure modes

The system uses adapters, registries, strategy-like matching, store interfaces, middleware/decorators, optimistic concurrency, bounded producer/consumer queues, and dependency inversion through callbacks (`NodeRecorder`, principal extraction). These patterns earn their place by isolating protocol or storage behavior; they are not an invitation to introduce additional frameworks.

Keep provider DTOs out of engine logic, tenant identity out of client-controlled selectors, role authorization separate from resource ownership, credentials out of logs, and background queues bounded. Avoid claiming that schema parsing validates all semantics or that a successful HTTP response means the intended scenario matched. Keep edits and persistence receipts honest when a file is unwritable or an optimistic precondition fails.

## Evolution and proposed improvements

Machine-readable core route/schema coverage and source-comment corrections are checked by the documentation tools; explicit compatibility-profile exclusions are listed in [contract scope](../api-contracts.md). Broader design changes should begin with an explicit need: bounded template caches for high fixture churn; shared session/catalog state for multi-replica operation; join/retry semantics for richer pipelines; and stronger capability/fidelity matrices for provider SDK versions. Each changes observable behavior and needs targeted acceptance tests, migration notes, and a compatibility decision.

Historical epics and design documents are useful context, but this suite does not treat unfinished proposals as shipped behavior. The [action register](../reviews/2026-09-18-action-register.md) records confirmed handoff gaps separately from these optional architectural directions.
